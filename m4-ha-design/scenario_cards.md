# M4. HA 시나리오 카드

카드를 하나 골라(또는 조별 배정받아) `ha_design_canvas.md`를 채웁니다. 각 카드는 강의에서 다룬 개념 중 하나를 실전 상황으로 압축한 것입니다.

## 카드 A: Active-Standby DB — Split-brain 위험

- 10:05 네트워크 단절 알람
- Primary와 Standby가 서로를 확인하지 못함
- 일부 애플리케이션은 Primary로, 일부는 Standby로 연결
- **목표**: Split-brain 방지, Failover 조건, 데이터 정합성, 롤백 기준 설계
- **연결 개념**: 세그먼트 2(Quorum/Fencing) — 2노드 구성이라면 애초에 자동 전환이 안전한가부터 되짚어볼 것

## 카드 B: Multipath 경로 장애 — 감지 임계값의 모호함

- 스토리지 경로 4개 중 2개 장애
- I/O latency 상승, 서비스는 아직 응답
- **목표**: 장애 판단 기준, 영향 최소화, 변경/복구 검증, SLO 영향
- **연결 개념**: 세그먼트 1(감지) — "완전 다운"이 아닌 "성능 저하"는 어느 시점에 장애로 선언하는가

## 카드 C: 변경 후 성능 저하 — 롤백 3요소 적용

- 커널 파라미터 변경 20분 후 응답시간 증가
- 명확한 장애는 아니지만 SLO 위반 임박
- **목표**: 롤백 트리거, 증거 보존, 승인/공지, 재적용 조건
- **연결 개념**: 세그먼트 3(롤백 3요소) — 트리거(무엇을 보고), 수단(무엇으로 되돌리는가), 소요시간(되돌리는 동안 서비스 상태)을 각각 명시할 것

## 카드 D: 멀티 리전/IDC 페일오버 후 재분산 (참고)

- 한쪽 데이터센터(IDC) 전체 다운, 워크로드가 살아있는 IDC로 자동 재배치되어 서비스는 유지됨
- 다운됐던 IDC가 복구된 후에도 워크로드가 계속 한쪽에만 몰려 있음
- **목표**: "전환"에서 끝내지 않고 "복구 후 재분산"까지를 하나의 사이클로 설계
- **연결 개념**: 세그먼트 2 — 전환은 성공했지만 재분산 단계가 빠지면 살아남은 쪽에 부하가 영구히 몰리는 2차 리스크가 생긴다는 것을 확인
